# Modify the WeData Agent

## Main File

**`agent_server/agent.py`** — Agent logic, model selection, instructions, MCP server configuration

## Key Files

| File | Purpose |
|------|---------|
| `agent_server/agent.py` | Agent core: model, instructions, MCP configuration, credential handling |
| `agent_server/utils.py` | Stream processing utilities (process_agent_stream_events) |
| `app.py` | FastAPI entry point, static file mounting, environment variable loading |
| `app.yaml` | App declaration: startup command, custom environment variables |
| `.env.local` | Local development credentials and configuration (not committed to git) |

## SDK Setup

The project already has SDK initialization configured — you typically don't need to modify this part:

```python
from agents import Agent, Runner, set_default_openai_api, set_default_openai_client
from agents.tracing import set_trace_processors
from wedata.openai import AsyncWedataOpenAI, RequestCredentialProvider

# WeData LLM client (handles TC3 signing automatically)
_wedata_client = AsyncWedataOpenAI(
    region=wedata_config.get("WEDATA_REGION", wedata_config.region),
    base_url=WEDATA_LLM_ENDPOINT,
    credential_provider=_credential_provider,
)
set_default_openai_client(_wedata_client)
set_default_openai_api("chat_completions")
set_trace_processors([])  # Use mlflow only for tracing
```

## Changing the Model

The model name is configured as a module-level variable in `agent_server/agent.py`:

```python
# ── LLM model configuration (change here to apply globally) ──
DEFAULT_MODEL = "deepseek-v3.2"
```

Change this line to switch models. Available models depend on the WeData platform configuration(check workspace for current list). Common options:

- `deepseek-v3.2`
- `deepseek-v3.1`
- `deepseek-v3.1-terminuus`

The model must support function calling for MCP tools to work. Restart to apply: `./scripts/start.sh`

## Adding MCP Tools

MCP tools are configured using a **base URL + path** pattern:

```python
# ── MCP base URL (read from platform-injected env var) ──
WEDATA_MCP_ENDPOINT = wedata_config.get("WEDATA_MCP_ENDPOINT", "")

# ── MCP tool path list (developers add MCP tools to connect here) ──
MCP_TOOL_PATHS: list[str] = [
    "/api/1.0/mcp/http/sql",
]
```

**Adding a tool = appending a path string to the `MCP_TOOL_PATHS` list.** At runtime, paths are joined to form `WEDATA_MCP_ENDPOINT + path`.

Common tool paths:

| Path | Function |
|------|----------|
| `/api/1.0/mcp/http/sql` | SQL query tool |
| `/api/1.0/mcp/http/metadata` | Metadata query tool |
| `/api/1.0/mcp/http/external/{key}` | Platform-registered MCP tool (e.g. Tavily search) |

After adding, restart: `./scripts/start.sh`

## Changing Instructions

The agent's system prompt is dynamically generated by the `_build_agent_instructions()` function, which auto-injects platform environment variables (app name, workspace ID, region, etc.).

There are two ways to modify it:

### Option 1: Edit the template function (recommended)

Edit the return string of `_build_agent_instructions()`. The current template structure:

```
## Identity
You are {WEDATA_APP_NAME}, an intelligent data assistant powered by the WeData platform.

## Runtime Environment
- Workspace ID / Region / Model (auto-injected)

## Core Capabilities
- SQL queries, data analysis, data catalog browsing, lineage tracing, etc.

## Guidelines
- Use tools to fetch real data, handle errors, format output, etc.
```

You can add, remove, or modify any section. For example, adding domain knowledge:

```python
f"## Domain Knowledge\n"
f"- This workspace primarily stores sales data; the core table is sales.orders\n"
f"- Monetary fields are in CNY (yuan)\n"
```

### Option 2: Full replacement (simple scenarios)

If dynamic environment variable injection isn't needed, you can hardcode the instructions directly in `create_coding_agent()`:

```python
def create_coding_agent(model: str, mcp_servers: list | None = None) -> Agent:
    return Agent(
        name="my-agent",
        instructions="You are an assistant focused on sales data analysis.",
        model=model,
        mcp_servers=mcp_servers or [],
    )
```

However, this loses runtime information like workspace ID, so it's not recommended for multi-environment deployments.

## Adding Local function_tools

In addition to MCP Servers, you can add local Python function_tools to the agent:

```python
from agents import function_tool

@function_tool
def my_custom_tool(query: str) -> str:
    """Describe what your tool does — the agent uses this description to decide when to call it."""
    return f"Result: {query}"

# Register in create_coding_agent
return Agent(
    ...
    tools=[my_custom_tool],  # Add to the tools list
)
```

To generate function_tool wrappers that call remote MCP endpoints (e.g. SQL query, table lookup), use the **wedata-local-mcp-example** skill.

## Running the Agent

The agent runs via two handlers (already implemented at the bottom of agent.py):

```python
# Non-streaming (invoke)
result = await Runner.run(agent, messages, max_turns=20)

# Streaming (stream)
result = Runner.run_streamed(agent, input=messages, max_turns=20)
async for event in process_agent_stream_events(result.stream_events()):
    yield event
```

`max_turns=20` limits the agent to 20 rounds of tool calls. If the tool chain is long, increase this value as needed.

## Architecture Overview

```
User request → app.py (FastAPI)
             → invoke_handler / stream_handler
             → _resolve_credential_headers()  # Obtain credentials
             → safe_mcp_context()             # Connect to MCP Servers
             → create_coding_agent()          # Create the Agent
             → Runner.run / run_streamed      # Execute inference
             → Return result
```

Credential handling is automatic:
- Local mode: reads credentials in AgentZ connector settings from `.env.local`
- Cloud mode: reads platform-injected STS credentials from request headers
