## 1. Background

Before the AgentZ 1.0 general-availability release, the current codebase and the historical upgrade ledger (`docs/upgrade/plan.json`) were reviewed in depth from three perspectives (advanced desktop user × Vibe Coder × professional IDE / agent-harness architect). Two classes of core problems were identified:

1. **Blocking on external physical resources and certificates**: some historical ledger items (`AZ-045` fault drills against a real controlled SSH remote, `AZ-058` / `AZ-077` / `AZ-078` verification on real macOS and Linux desktop sessions and system keychains, `AZ-064` commercial code-signing certificates and Apple Notarization, `AZ-068` traffic-split telemetry with an external real beta user group, `AZ-057` 2-hour long-run sampling on a dedicated physical machine) depend on hardware, accounts or commercial certificates outside the local engineering environment.
2. **"Anti-Human" isolated compliance components produced by mechanically matching the ledger wording**: to satisfy, in isolation, the literal "observe only, never over-promise" requirements of `AZ-020`, `AZ-024`, `AZ-035`, `AZ-038`, `AZ-039` and `AZ-050`, the codebase grew several isolated components that were not mounted on any real user path and were full of internal status words and disclaimers:
   - `src/workspaces/codez/BudgetObservation.tsx`: showed users "millionths of a currency unit (micro-units)" directly, plus a 9-line disclaimer;
   - `src/workspaces/codez/DeliverySummary.tsx` and `src/workspaces/codez/DeliveryReviewPanel.tsx`: printed stiff disclaimers such as "an execution delivery decision does not mean a given artifact version has been accepted" and "this is not an atomic snapshot", without any actual review-and-merge action;
   - `src/workspaces/codez/DurablePlanActions.tsx`: required users to fill in a separate form to replace the plan goal, detached from the conversation flow;
   - `src/workspaces/codez/TaskArtifactViewer.tsx` and `src/workspaces/codez/TaskFileViewer.tsx`: required users to type `relativePath` and `title` by hand and trigger `Capture / Reconcile` manually;
   - `src/workspaces/workz/index.tsx` and `src/workspaces/workz/AgentTaskReview.tsx`: exposed `working/commit` and `HEAD` SHA input boxes directly in the main UI's bottom bar, and locked the merge button whenever the worktree had uncommitted changes.

## 2. Core decisions

### 1. Admission by engineering code and local automated gates (`waived:ADR-006`)

- **Hard bar for 1.0**: every capability that can be closed out through local source implementation, TypeScript type checking, Vitest unit/component tests, Rust unit/integration tests, local fixture migration verification and Playwright E2E automated gates is a mandatory admission condition for the 1.0 release.
- **Controlled waiver for external physical and commercial resources**:
  - Acceptance items that cannot be executed locally solely because of missing external macOS/Linux physical machines, external controlled SSH hosts, commercial code-signing certificates/notarization accounts, or an external real user group (related to `AZ-031` cross-platform credential prerequisites, `AZ-045`, `AZ-054` real cross-window focus, `AZ-057` 2h dedicated sampling, `AZ-058`, `AZ-064`, `AZ-068`, `AZ-077`, `AZ-078`) are uniformly given a `waived:ADR-006` controlled waiver or moved to the `1.x` cross-platform expansion cycle (`deferred`), and the support boundary is stated truthfully in `docs/upgrade/evidence/AZ-005-support-matrix.md`.
  - M9 multi-agent teams and automation enhancements (`AZ-070`–`AZ-076`) are uniformly labelled as `Beta` experimental features, collapsed by default in the UI, and do not block the 1.0 release of the core single-agent and dual-view hand-off.

### 2. Anti-bureaucracy and natural interaction flow (Human-Centric UX Mandate)

Abolish the practice of "writing isolated read-only disclaimer components to pass the ledger", and remap the acceptance criteria of the related ledger items onto real, mounted main-UI interaction flows:

- **Budget and cost display (corrects `AZ-024` / `AZ-035` / `AZ-040`)**: retire `BudgetObservation.tsx` and `TaskDetailsPanel.tsx`; show real-time tokens and converted cost in human-readable form (e.g. `12.4k tok · $0.02`) in `IdeStatusBar.tsx` and `ContextUsageRing.tsx`, with one-click model switching from the status bar.
- **Durable plan interaction (corrects `AZ-020`)**: retire `DurablePlanActions.tsx`; integrate durable-plan querying and state recovery seamlessly into `TaskPanel.tsx`, automatically restoring unfinished plan items when a session loads, with a simple clear button.
- **Change review and delivery merge (corrects `AZ-038` / `AZ-039`)**: retire `DeliverySummary.tsx` and `DeliveryReviewPanel.tsx`; consolidate into `WorkZ`'s `AgentTaskReview.tsx`, which supports one-click automatic stage-commit-and-merge into the main branch when the worktree has uncommitted changes, eliminating the deadlock.
- **Artifact preview and document editing (corrects `AZ-036` / `AZ-038` / `AZ-050`)**: retire `TaskArtifactViewer.tsx` and `TaskFileViewer.tsx`; upgrade `WorkZ`'s right-hand `AgentFilePreview.tsx` into an editable canvas supporting `Preview / Edit / Diff`, direct save and "continue the conversation with this change", and provide a one-click "open the isolated worktree in CodeZ" in the top bars of `AgentTaskReview` and `AgentFilePreview`.
- **The UI must never expose internal storage terms**: no user-facing UI component may output low-level implementation terms such as `store_missing`, `requiresReconcile`, `micro-units` or `not an atomic snapshot`.

## 3. Audit and verification requirements

1. The ledger validation script `node scripts/upgrade-plan.mjs validate` and the isolated regression `node scripts/upgrade-plan.verify.mjs` must keep passing with zero errors.
2. All 24 atomic 1.0 tasks (`R10-01` to `R10-24`) must produce corresponding automated tests and `docs/upgrade/evidence/R10-*.md` audit evidence.
