# ADR-006：AgentZ 1.0 纯工程自动化准入与反官僚化体验基线

状态：已接受（用户决定，2026-10-19）

## 一、背景

在推进 AgentZ 1.0 正式版发布前，综合三方视角（普通进阶桌面用户 × Vibe Coder × 专业 IDE / Agent Harness 架构师）对当前代码库与历史升级台账（`docs/upgrade/plan.json`）进行了全面审查，识别出两类核心问题：

1. **外部物理资源与证书阻塞**：部分历史台账条目（`AZ-045` 真实受控 SSH 远端网络故障演练、`AZ-058` / `AZ-077` / `AZ-078` macOS 与 Linux 真机桌面会话及系统钥匙串验证、`AZ-064` 商业代码签名证书与 Apple Notarization 公证、`AZ-068` 外部真实 Beta 用户群分流遥测、`AZ-057` 2 小时独占物理机长稳采样）依赖本机工程环境之外的外部硬件、账号或商业证书。
2. **机械迎合台账字面条款导致的“反人类（Anti-Human）”孤立合规组件**：前期为孤立满足 `AZ-020`、`AZ-024`、`AZ-035`、`AZ-038`、`AZ-039`、`AZ-050` 的“仅观察、不越权承诺”字面要求，代码库中衍生出若干未挂载到真实用户主路径、充斥内部状态词与免责声明的孤立组件：
   - `src/workspaces/codez/BudgetObservation.tsx`：向用户直接展示“百万分之一货币单位（micro-units）”及 9 行免责声明；
   - `src/workspaces/codez/DeliverySummary.tsx` 与 `src/workspaces/codez/DeliveryReviewPanel.tsx`：向用户输出“执行交付决策不代表某个产物版本已验收”、“此处不是原子快照”等生硬免责声明，却无任何实际审阅合入动作；
   - `src/workspaces/codez/DurablePlanActions.tsx`：要求用户手填独立表单替换计划目标，脱离对话流；
   - `src/workspaces/codez/TaskArtifactViewer.tsx` 与 `src/workspaces/codez/TaskFileViewer.tsx`：要求用户手填 `relativePath`、`title` 并手动触发 `Capture / Reconcile`；
   - `src/workspaces/workz/index.tsx` 与 `src/workspaces/workz/AgentTaskReview.tsx`：在主界面底栏直接暴露 `working/commit` 及 `HEAD` SHA 输入框，且在工作树存在未提交改动时直接锁死合入按钮。

## 二、核心决策

### 1. 纯工程代码与本地自动化门禁准入（`waived:ADR-006`）

- **1.0 必过硬门槛**：所有可通过本地源码实现、TypeScript 类型检查、Vitest 单元/组件测试、Rust 单元/集成测试、本地夹具迁移验证及 Playwright E2E 自动化门禁闭环的能力，均作为 1.0 正式版强制准入条件。
- **外部物理与商业资源受控豁免**：
  - 对仅因缺少外部 macOS/Linux 物理机、外部受控 SSH 主机、商业代码签名证书/公证账号、或外部真实用户群而无法在本地执行的验收项（关联 `AZ-031` 跨平台凭据前置、`AZ-045`、`AZ-054` 真实跨窗口焦点、`AZ-057` 2h 独占采样、`AZ-058`、`AZ-064`、`AZ-068`、`AZ-077`、`AZ-078`），统一采用 `waived:ADR-006` 受控豁免或移入 `1.x` 跨平台扩展周期（`deferred`），并在 `docs/upgrade/evidence/AZ-005-support-matrix.md` 中如实声明支持边界。
  - M9 多 Agent 团队与自动化增强（`AZ-070`–`AZ-076`）统一标记为 `Beta` 实验特性并在 UI 默认折叠，不阻塞 1.0 核心单 Agent 与双视图交接发布。

### 2. 反官僚化与自然交互流准则（Human-Centric UX Mandate）

废除“为通过台账而编写孤立只读免责声明组件”的做法，将相关台账条目的验收标准重映射至真实挂载的主界面交互流：

- **预算与费用展示（纠偏 `AZ-024` / `AZ-035` / `AZ-040`）**：清退 `BudgetObservation.tsx` 与 `TaskDetailsPanel.tsx`；在 `IdeStatusBar.tsx` 与 `ContextUsageRing.tsx` 中以人类可读格式（如 `12.4k tok · $0.02`）展示实时 Token 与折算费用，并支持状态栏一键切换模型。
- **持久计划交互（纠偏 `AZ-020`）**：清退 `DurablePlanActions.tsx`；将持久计划查询与状态恢复无缝集成至 `TaskPanel.tsx`，随会话加载自动恢复未完成计划项，并提供简洁的清空按钮。
- **变更审阅与交付合入（纠偏 `AZ-038` / `AZ-039`）**：清退 `DeliverySummary.tsx` 与 `DeliveryReviewPanel.tsx`；统一收敛至 `WorkZ` 的 `AgentTaskReview.tsx`，当工作树含未提交改动时支持一键自动暂存提交并合入主分支，消除死锁。
- **产物预览与文档编辑（纠偏 `AZ-036` / `AZ-038` / `AZ-050`）**：清退 `TaskArtifactViewer.tsx` 与 `TaskFileViewer.tsx`；将 `WorkZ` 右侧 `AgentFilePreview.tsx` 升级为支持 `Preview / Edit / Diff`、直接保存与“带此修改继续对话”的可编辑画布，并在 `AgentTaskReview` 与 `AgentFilePreview` 顶栏提供一键“在 CodeZ 中打开隔离工作树”。
- **UI 严禁暴露内部存储术语**：任何面向用户的界面组件严禁直接输出 `store_missing`、`requiresReconcile`、`micro-units`、`not an atomic snapshot` 等底层实现术语。

## 三、审计与验证要求

1. 台账校验脚本 `node scripts/upgrade-plan.mjs validate` 与隔离回归 `node scripts/upgrade-plan.verify.mjs` 必须保持零错误通过。
2. 所有 24 项 1.0 原子任务（`R10-01` 至 `R10-24`）必须产出对应的自动化测试与 `docs/upgrade/evidence/R10-*.md` 审计证据。
