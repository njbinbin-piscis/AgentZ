# Windows候选发版后的下一轮原子计划（草案）

2026-10-07。按用户要求，本轮先形成可审阅的 Windows x64 unsigned 0.9.7 候选，再同步推进下轮。版本元数据准备不等于实际包/发版已完成；本文件未触发构建、CI、提交或发布，也未修改 plan.json。

用户允许缺资源验收跳过并记录。本轮“后移”只表示排期，不表示 GUI、真实模型、跨平台、签名或安装已通过。总路线图 done 与 Gate 保持真实；下述任务仍 pending，不能按草案直接绕过当前脚本规则开工。

## 可审阅 ADR-005 修订草案：分开代码依赖与验收依赖

目前 preparing 仍要求所有任务依赖 done，因此 AZ-017 实现和自动测试已交付但 GUI/模型/M1未验收时，AZ-018等代码工作全部停住。建议主线程审阅以下增量规则，再通过脚本实现并跑隔离验证，不先伪造 AZ-017 done。

1. 原 dependencies/Gate作为验收依赖保持。doing/review/done与里程碑passed的约束不变；缺GUI/模型/平台资源永远不能自动变成通过。
2. 候选开工可声明单独 `code_dependencies`。上游 done 仍满足；上游 review/preparing 只有在其**限定代码契约**有独立复核、最新源码指纹、针对自动验证及编译结果、已知验收缺口时，才能形成 `implementation_accepted` 记录。此记录不是任务完成数，也不能赋予正式review/done权限。
3. 主线程为每条代码依赖明确所消费的接口版本/指纹与验收范围；禁止仅凭“有代码”或构建未退出取得开工资格。上游候选变更/验证失败使记录失效，消费它的下游必须重验证，不能持续沿用旧批准。
4. 新分离规则必须先以隔离夹具验证：未复核候选依赖拒绝、最新复核可仅preparing、上游指纹变化拒绝、Gate未过仍拒绝review/done、失败不写正式台账、task done/Gate计数不变。所有台账写入仍由主线程通过 upgrade-plan.mjs串行处理。
5. 这是针对已交付接口消除工程排期阻塞，不是忽略真实验收；同样不能让缺外部动作授权/证书/平台的任务执行外部副作用。未采纳草案前只可进行只读设计与夹具规划。

## 并行节奏与跟踪

- 第一波：主线程先完成ADR草案审阅/台账隔离验证以及AZ-017限定代码契约复核；随后最多3个子代理分别NC-01/02/03，主线程负责接线、检查与统一验收。不同时启动多个Rust全量构建。
- 第二波：NC-01/02契约稳定后推进NC-04/05/06，共享文件由主线程串行接线；NC-08只在schema冻结后开始，避免备份格式追逐在途变更。
- 第三波：NC-06稳定后实施NC-07，再按原依赖推进AZ-041脏缓冲保护等后续项。真实GUI条件缺失时记录pending验收，不能让未保存内容保护被“跳过”并宣称可靠。
- 每包记录开始前源码指纹、依赖契约、实际修改、执行命令/退出码、失败与修复、未验收条件、下个可执行动作。主线程review实现结果，统一通过脚本更新候选记录；发布/部署仍对应具体审阅产物独立操作。
