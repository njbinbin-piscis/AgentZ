# AZ020 opened project scope primitive

Added only runtime/project_scope.rs and this evidence, post-0.9.7. No state/module/IPC registration, Cargo, model or GUI run. Formatting/diff checks passed;3 fixtures were written but not run by this agent.

ProjectScopeRegistry stores bounded host-owned opaque UUID handles, canonical local directories, trusted window labels/generations and open-source metadata. Private VerifiedProjectScope fields are obtainable only from host mint/lookup; getters expose reviewed identity without allowing renderer assembly. Same window can retain multiple projects; canonical duplicate roots reuse a handle, preserving original provenance. Budget exhaustion explicitly rejects new scope rather than silently evicting or expanding. Default maximum128 scopes and8 window identities; closed-window generation watermarks are retained within that budget.

begin_window requires a strictly newer nonzero generation and revokes older same-window scopes. revoke removes an individual opened scope; close_window removes scopes and closes the generation, so that generation cannot mint anew. lookup rejects unknown/revoked handle, wrong window and stale/closed generation before any database access. No plan/session/database is opened by this primitive. Canonical existing directory is a storage/path prerequisite, not filesystem ownership or user authorization proof.

Mint is host-internal only and records NativePicker/RestoredWorkspace/TrustedGuiOpen source. Root must connect to trusted main-GUI/native-picker/host-restore lifecycle and keep model/extension bridges unable to mint. This draft does not establish that Tauri boundary or attest native-picker origin merely from the enum value. Caller must derive window/generation from host, use lookup afresh for each operation, verify existing project-local session/registered workspace, and coordinate scope revocation with the actual command task gate. A previously returned VerifiedProjectScope is an immutable identity snapshot, not a live lease and not an execution grant; it cannot prove ongoing revocation immunity.

Fixtures cover unknown/window/generation/revoked lookup, close then mint refusal, canonical duplicate/multiple-project separation and restart, budget rejection without eviction and missing-root refusal. Root must export/run these fixtures and integrate source/lifetime checks before chat-plan IPC activation. No current renderer/capability behavior is claimed changed.
