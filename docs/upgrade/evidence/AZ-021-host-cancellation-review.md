# AZ-021 host cancellation-finalization independent review

Read-only review of current chat_turn capture/drain/finalization, durable_run request_cancelling and cancel_completion service plus kernel receipt sites. No Cargo/source/ledger changes. Parent94796 three host fixtures were compiling when assigned; no passing claim here.

P2 concrete flag race: chat_turn first checks cancel at the drain decision and computes cancellation_unconfirmed=false when the flag is false. Later finish and lifecycle independently load the flag again. A Stop arriving between those points can mark the Run Cancelled without request_cancelling or any receipt drain. Capture a single finalization decision (requested + confirmed) and use it for BOTH durable finish and lifecycle; finishCancelled must be capturedRequested && confirmed && !durabilityFailed, never a later flag alone. If handling a later Stop is desired, rerun the unified drain decision rather than silently promote a subsequent flag read. A meaningful fixture must force Stop between initial decision and terminal arguments and demonstrate no undrained Cancelled.

Coverage boundary: Complete from an empty registry proves only that zero registered local cooperative workers remain. It does not prove cancellation of unregistered browser/SSH/subagent/MCP/remote/pool/background actions or remote requests. Current capture runs for all contexts; kernel receipts exist only at supported local sandbox shell/code_run worker closures. At minimum gate any Cancelled confirmation claim to supported local single-agent contexts and explicitly treat an in-flight unsupported action as unconfirmed/Interrupted. Stronger solution is invocation-owned receipts around EVERY tool dispatch (with abandoned futures marked Failed), plus worker-owned receipts for blocking/subprocess cleanup and an explicit containment contract; do not infer universal cleanup from the tool list or a flag. Empty text-only attempt may finish cancelled as an agent-loop outcome but must not be described as all external resources cancelled. Unknown budget/request billing remains separate.

Positive boundaries: capture precedes agent.run and retains the exact attempt cancellation Arc; wait_requested checks full captured binding and positive bounded timeout. request_cancelling persists Cancelling before drain. Pending/Failed are treated Interrupted by the current intended branch and never automatically rerun tools. In chat_send the caller semaphore permit, task registration/gate and environment lease remain held through run_agentz_turn/drain/terminal commit; they are not moved into the drain registry. The real service fixture demonstrates held taskgate/slot for a delayed registered worker, not a whole native tool journey.

Outer timeout of agent.run drops its future and then sets cancel=true; supported worker receipt lives inside its spawn_blocking closure, so dropping that tool future does not by itself acknowledge cleanup. The retained completion registry can still drain it. Aborting the entire chat IPC/host future is different: ManagedRun Drop persists Interrupted synchronously but cannot await drain, and TaskRegistration async drop cleanup releases its gate later. This is not a false Cancelled but it does not prove all workers finished before resources became available; preserve as an explicit unresolved crash/abort/containment limit. Shutdown/drop failures are reconciliation cases, never inferred safe replay.

Formal AZ021 team/model/subagent/pool/remote/provider/cross-platform/native GUI cancellation acceptance remains incomplete. This candidate only improves supported cooperative local shell/code_run cleanup finalization and timeout visibility.
