# AZ-061 local diagnostic redaction candidate (2026-10-14)

The existing log export previously ignored secret strings shorter than eight bytes and only collected values from settings. It now redacts every nonempty settings secret value, reads the current `connectors/<id>/credentials.json` files at export time (including rotated tokens), and treats every connector credential string field as secret. Unreadable, malformed, non-regular or oversized credential files fail the export before writing a bundle. Log selection is capped at 32 regular files and 8 MiB total and rejects symlinks/oversize inputs before writing an export.

The six scoped `diagnostics::tests` passed in `agentz-desktop`, including short secret, connector rotation, malformed credential and oversized log cases. `git diff --check` passed for the edited file. No real user bundle was exported or sent.

This is a local safety improvement, not AZ-061 acceptance. Task/run/tool/environment manifest correlation, previewable export range, non-settings secret providers, encoded secret forms and the AZ-031 secret-reference dependency remain to be addressed. Keep the task pending for unified review.

Follow-up: log redaction now also masks URL percent-encoded (upper- and lower-case hex) and standard/URL-safe base64 forms of known secrets, including unpadded forms. One- and two-byte secrets stay literal-only to avoid broad encoded-text replacement. A mixed-case, non-ASCII fixture covers these forms; all seven scoped `diagnostics::tests` passed after the final change. This does not establish that every secret source or encoding is covered; the manifest, preview and AZ-031 dependency remain open.

Further follow-up: `diagnostics_preview_logs` returns a versioned, bounded list of log basenames and byte counts after checking the same current connector credentials that export uses. It returns no log contents or secret values and fails closed on malformed credentials. The Settings model pane now requires a successful scope preview before offering a local export button; export independently rechecks its inputs. Eight scoped host tests, a focused settings rendering test, TypeScript noEmit and production frontend build passed. The preview is only a log-file scope summary; task/run/tool/environment correlation, full secret-source inventory, native desktop interaction and AZ-031 remain open.

MCP follow-up: diagnostic export now includes current MCP command, URL, arguments, environment and header values in its secret set, regardless of provider-defined field names. A synthetic marker in all five surfaces is absent from an actual local exported log, while ordinary server name and transport are excluded from the secret set. `cargo test --manifest-path src-tauri/Cargo.toml mcp_values_are_redacted_without_masking_server_identity --lib --locked --offline` passed 1/1. The complete source inventory, reference contract, native preview/export journey and correlation manifest remain open.

The local exported log now starts with a bounded JSON manifest identifying source log filenames/byte counts and up to 100 WARN/ERROR file-line locators. For lines carrying an `agent_turn{...}` tracing span, safe-length task, run, environment and optional tool-name fields are extracted after secret redaction. The manifest records when the locator cap was reached. A synthetic fixture confirmed source file/line and correlation fields while the secret marker was absent from the final export; the scoped diagnostics suite passed 10/10 on Windows. Real logs may omit some fields, especially tool name; this is a source-level candidate, not complete task/run/tool/environment correlation or native export acceptance.

Bounded export follow-up: the export now opens each selected log and verifies its size against the previewed metadata, then reads at most that many bytes plus one. Growth or truncation during export fails closed, rather than allowing an unbounded read from a concurrently changing log. A direct growth/truncation fixture and all 11 scoped diagnostics tests passed on Windows. This does not prove source identity against every path replacement race or provide native export acceptance.

Tool-error correlation follow-up: the durable event collector now carries the turn tracing span and emits a WARN when a tool ends in error, logging only a bounded allowlisted tool name and a fixed message. The export locator accepts the tool name as a tracing event field as well as a span field. A two-line synthetic export fixture covers both placements with run/task/environment identity, and all 11 scoped diagnostics tests pass on Windows. This is source-level correlation; a real failing tool and native export journey have not yet been observed.

Gateway source audit follow-up: Feishu and DingTalk auth/send/stream errors and WeChat send/update/upload/download HTTP failures previously included untrusted provider response bodies or messages in logs/errors. Those paths now report bounded status/code or fixed missing-field text without copying response payloads, which can echo credentials or ticket material. `cargo check --manifest-path src-tauri/Cargo.toml --locked --offline`, rustfmt check and diff whitespace check passed on Windows. This is a bounded source audit of three gateway adapters, not proof that every log source or provider error path is secret-safe.

The Feishu image/file upload and send failure branches were also found to include the provider's untrusted `msg`; those now report only HTTP status and an integer error code. The text-send code is likewise coerced to an integer before formatting. A subsequent offline desktop cargo check, rustfmt check and diff whitespace check passed. No gateway live request was issued.

WeChat CDN upload/download use signed or encrypted query parameters. Transport errors from those requests now become fixed error text, avoiding accidental disclosure of a URL carried by a client error. A no-network invalid-URL fixture embeds a synthetic query marker and verifies the returned upload error omits it; the focused Rust test passed 1/1 on Windows. This does not cover every URL-bearing network error elsewhere.

The connector HTTP tool and iLink QR-code request were then reviewed for the same outlet: failed connector requests no longer include client error URLs or provider response bodies, and failed QR requests report only fixed text or HTTP status. Successful connector responses remain tool results. The targeted edits were made on top of existing modified files; an offline desktop cargo check, rustfmt check and diff whitespace check passed. This remains a partial source audit, not a complete secret-outlet certification.

The iLink QR polling URL also contains the user-provided QR token as a query parameter. Its transport and JSON-decode errors now return fixed text rather than formatting the reqwest error, which could carry that URL. The status-code branch was already bounded. Offline desktop `cargo check`, rustfmt check and diff whitespace check passed on Windows. No live QR login or failing network request was run; the broader outlet inventory remains open.

Webhook URL redaction follow-up: diagnostic secret collection previously used key-name hints that omitted Slack, Discord, Teams and generic outbound webhook URL fields. Those four exact fields now join the redaction set from decrypted settings; a synthetic marker fixture confirms a webhook URL is removed while an unrelated public URL remains outside the set. Focused Rust test passed 1/1 on Windows. Native export and the complete source inventory remain unverified.

The URL rule was then expanded from those four names to any settings key named `url` or ending in `_url`, since model/custom/MCP-style base URLs can also contain userinfo, path or query credentials. The fixture now includes `custom_base_url` and a non-URL public field; it passed 1/1 on Windows. This deliberately masks otherwise public URL values in diagnostic logs. The native export and non-settings source inventory remain open.

Connector-scope hardening, 2026-10-16: diagnostic preview/export now fail closed if the `connectors` root is not a real directory or an immediate child is a symbolic link. Previously a linked child was silently skipped, so its credential values could be absent from the redaction set. The fixture uses Windows junctions, which this host can create without symlink privilege, and confirms that both a linked root and a linked child are rejected before an export file is created. `diagnostics::tests` passed 13/13 with `--offline --locked` on Windows; the edited file passed `rustfmt --check` and `git diff --check`. The workspace-wide formatter check remains blocked by pre-existing formatting in `src-tauri/examples/graph_verify.rs`. Native export and full secret-source inventory remain open.

Log-path scope hardening, 2026-10-16: preview/export now reject a linked `logs` root and propagate unreadable log directory entries instead of silently omitting them. Export also rejects a linked `exports` root before writing. A Windows junction fixture verifies rejection of both roots and no output in the external directory; the diagnostics suite passed 14/14, with targeted rustfmt and diff checks passing. This is a local path-scope check, not a native UI export or a complete secret-source audit.

Export collision hardening: each diagnostic export now uses a unique filename and create-new semantics, so a second request in the same clock second does not overwrite an earlier redacted export or follow an existing file link. The local fixture checks two distinct outputs and preservation of the first; the Windows diagnostics suite passed 14/14. Native export remains untested.
