# AZ-001 · 首批用户与产品旅程契约

基线：a787b6d（0.9.6），2026-10-04。用户授权开始路线图实施。本轮由Codex执行，复核为同一执行者自检，未取得独立用户验收。

首批用户为在本地或SSH工程中工作的开发者；他们需要亲自编辑，也需要将代码、代码研究和文档交给Agent完成。CodeZ与WorkZ共用Task和Environment，视图切换不新建任务或改变执行根。

## J1 修复真实工程问题

输入：工程、具体错误、预期行为、起点和授权。输出：可查看的完整ChangeSet、测试结果、未验证项及可应用版本。

路径：创建任务→确认环境→Agent执行→停止/接手→CodeZ人工修改→同任务续聊→评审→应用或PR→归档恢复。

验收：A/B交叉续聊与重启不串环境；未提交与新文件进入评审；脏缓冲不覆盖；应用前核对HEAD与冲突；不自动发布；归档恢复内容一致。

## J2 带来源的代码研究

输入：明确问题、工程、允许读取范围。输出：带文件路径/版本来源的报告、推断与未确定事项。

路径：创建只读任务→检索/读取→报告产物→用户补充约束→同任务修订→验收。

验收：只读权限实际生效；来源可定位；推断与事实分开；报告可打开、保存和版本追踪；不因模型停止输出而自动标记验收成功。

## J3 无仓库文档任务

输入：文档目标、资料、指定输出目录和格式（首期Markdown/HTML）。输出：可预览、人工编辑、修订和归档的文档。

路径：独立任务环境→生成文档→预览→人工编辑→续聊→验收→归档。

验收：不隐式git init/commit；重开仍使用原目录；人工改动进入后续上下文；清理只处理登记的任务环境，不删除用户目录。

## 承诺范围

每轮显示目标、运行路径、环境身份、模型与授权摘要；有明确停止/阻塞/中断状态；交付动作与执行状态分开。首期优先修复J1的环境与变更正确性。

暂不承诺任意VSIX完全兼容、任意应用无人监督操作、企业多租户、移动端和云托管。真实模型质量、首次使用与三平台体验须经过后续样本验收，不以本契约替代实测。

完成复核：三条旅程均包含输入、产物、路径、授权与验收；范围已关联M1–M8。下一步为AZ-002固化身份契约和AZ-003固化回归夹具。
