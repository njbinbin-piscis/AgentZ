# AZ025 external action intent contract candidate

2026-10-09. Planned independent external_action.rs domain module; no real send/PR/post/deploy, host IPC or provider authorization. Implementation starts only after root records limited AZ019 code dependency review. Existing AZ018 event identity and AZ019 no-blind-replay semantics are consumed without claiming formal Gates passed.

An action is identified by canonical project plus stable root task/action key. Immutable provider, kind, target digest and payload digest prevent a reused key from describing a different side effect. No commands, bodies, credentials or raw provider errors are persisted. Binding origin is checked against authoritative existing Run/Attempt in the same SQLite transaction. Action remains task-stable across attempts; a retry must discover the existing action, never silently reset it.

Proposed APIs: existing-only store open, explicit independent schema1 initialization, read-only query without initialization; prepare returns Created or Existing (neither authorizes network); start requires exact revision, fresh current Running attempt and returns a non-Clone owned StartPermit only after durable CAS to Started. Only that first permit permits one caller-controlled dispatch. Restart/repeated start returns no permit. States Prepared, Started, Unknown, Confirmed, Failed are versioned. Started after a crash is unresolved, not evidence of failure; query requires reconciliation just like Unknown. No automatic retry operation exists.

Completion persists a bounded opaque receipt digest; lost result becomes Unknown. Trusted provider query/manual evidence may confirm success or prove definitive no-effect failure. An ordinary Err, timeout, cancellation, transport failure or missing receipt cannot mean definitive Failed. Terminal states do not reissue permits; a new semantic action needs an explicit new key and future host authorization. This module cannot ensure a provider honors idempotency or prevent a caller misusing a permit; it records local authorization once, not distributed exactly-once execution.

Immediate transactions serialize competing connections. Namespace version/table/layout/record corruption and overflow must fail closed, not repair. Namespace is independent of Run user_version, and existing database noCREATE semantics are retained. Every mutation validates task history and captured origin; read validates stored scope/records. External member enrollment and renderer-provided roots are not supported.

Required real SQLite fixtures: duplicate preparation is a non-executable Existing result; concurrent start yields exactly one permit; controlled local service succeeds then loses result, reopened Started/Unknown cannot dispatch again and explicit receipt reconciliation confirms one service effect; conflicting immutable key scope rejects; old attempt cannot newly start; completion SQL failure leaves durable unresolved state; missing/schema0/future/partial/corrupt storage is not repaired. Fixtures have not run yet. Root owns module registration, Cargo, independent review and ledger updates. No real provider or desktop acceptance is claimed.
