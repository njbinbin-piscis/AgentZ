# AZ-048 projectless first-turn integration gap (2026-10-14)

Current-source trace: `projectless_session_create` persists a session-to-directory mapping in the app-data catalog, while WorkZ's new-task path still generates its own UUID and sends `freeCwd`; the new host API is used only by its service tests. Wiring that API directly into WorkZ is insufficient: `chat_turn.rs` replaces the shared free-session root with the managed directory, then sets `require_binding` when the workspace differs from the project. `ApprovalHooks::new_with_identity` repeats the same rule. Both call `resolve_binding` -> `resolve_task_workspace`, which currently accepts only a registered `TaskEnvironment` when `require_binding` is true. A projectless catalog entry is not a `TaskEnvironment`, so a bound first turn is refused with “isolated task has no registered environment”. No native/model run was attempted or claimed.

The required fix is a host-trusted projectless binding mode that checks the actual app-data catalog and session mapping at initial resolution and on every approval/tool recheck. It must also be consumed by task observation and continuation, without treating a renderer-supplied workspace path or a fabricated catalog as authority. Existing legacy free sessions remain on their current route pending an explicit migration policy.

Implementation update (2026-10-15): `chat_turn` now resolves the managed directory from Tauri app data before prompt/file-reference expansion and carries that host-selected catalog through the initial binding and `ApprovalHooks` rechecks. A conflicting registered environment, redirected directory, wrong session, and lost catalog fail closed. The verified workspace is persisted in the session row only when previously absent; a conflicting saved workspace refuses continuation. `chat_plan` and `task_view` read the same catalog binding and compare it with saved session metadata, including a second check before read-only observation returns. WorkZ requests a host-created session before optimistic task display and uses its managed directory; reopening uses a host lookup that returns `null` for legacy free tasks and errors on catalog loss. The managed directory is displayed and its CWD picker is locked while the task is selected.

Verification: desktop `cargo check -p agentz-desktop` and frontend `npm run typecheck` passed after integration; 12 project-scope client tests passed. The new native approval fixture passed with two independently bound sessions, cross-session/root denial, denial without the catalog mode, and lost catalog denial. `upgrade-plan.mjs validate` passed with historical warnings. No real model turn, native GUI journey, task recovery, cross-platform, or rollback acceptance was run. AZ-048 remains `preparing` until unified review and those journeys are verified.
