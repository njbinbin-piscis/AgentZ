# AZ-017 implementation dependency review

2026-10-07, read-only review during the 0.9.7 packaging freeze. Only this evidence file was written. No source, ledger, build, model, or desktop operation was performed. This review supports main-agent assessment of proposed ADR-006; it does not enact that proposal or mark AZ-017 accepted.

## Consumable interfaces

`agentz_task_state::run::RunStore::open(project)` canonicalizes the project, stores `.agentz/runs.db`, enables foreign keys and a five-second busy timeout. Schema user_version 1 owns runs/attempts and the unique active-task index; newer schemas fail closed. The Connection is private. It is synchronous SQLite storage, not an event subscription service.

`create(run_id, task_id, environment_id, attempt_id, now_ms)` requires a registered task environment. `create_direct(binding, now_ms)` accepts a host-validated direct snapshot, checks canonical project/unregistered task and fingerprint shape, and does not freeze or register a TaskEnvironment. `load(run_id)` returns run/task/environment/current-attempt IDs, Execution, Delivery and updated_ms. `attempts(run_id)` exposes attempt history and timestamps. `transition` uses expected execution + current attempt + nondecreasing timestamp and commits Run and Attempt together. `retry` preserves terminal attempt history and creates a new queued attempt; successful runs cannot retry. `decide_delivery` allows one human Accepted/Rejected decision from succeeded/awaiting_review and performs no publication.

Execution has Queued, Running, Cancelling, Succeeded, Failed, Cancelled, Interrupted; Delivery separately has NotReady, AwaitingReview, Accepted, Rejected. These serialized snake_case values are available candidate contracts, not proof of desktop recovery.

`ManagedRun::queue_bound/start_bound` records queued managed/direct execution and verifies the stored queue binding before starting. `identity` exposes run and attempt. `finish` persists success/failure/cancel/timeout; Drop best-effort interrupts unfinished execution and logs persistence failures. `begin_bound` supports the shared background entry. Drop is not crash reconciliation and does not execute after process death. Cancellation is observed through the host's AtomicBool and slot ownership, not a durable cancellation request table.

`ApprovalHooks::new_with_identity` accepts distinct host-generated run/attempt IDs, resolves canonical environment binding, and validates the shape. Its binding accessor is pub(crate). Tool execution fresh-checks task/environment/workspace, retaining the attempt ID. Binding includes project/task/environment/binding_version/run/attempt/capability_version. Approval persistence is a separate approvals.db; shape validation grants no execution rights. Legacy `new` still uses a single identity for compatibility and is not a durable retry entry.

Subject to main-agent review and formal ledger rule changes, pure candidate schema/policy modules can consume these narrow contracts. Existing gates and actual acceptance requirements remain unfulfilled. This document does not authorize downstream activation under today's dependency checker.

## Two integration gaps requiring explicit resolution

1. **AZ-018 atomic event integration:** RunStore owns a private Connection, commits transitions internally, and rejects schema >1. A separate event database or independently committed event append cannot guarantee no state-without-event window. Agree a same-transaction event/outbox API and migration ownership with AZ-017 before claiming durable lifecycle streaming. This blocks correctness of host event integration, not isolated event-library drafting.
2. **Durable retry/approval integration:** RunStore::retry has no host retry constructor or restartable ManagedRun load path; guard constructors create new Runs and approvals are bound to independently supplied Attempt IDs. A durable retry cannot safely be wired by only calling retry then starting a regular new-turn constructor. Define a host resume/attempt contract with fresh environment and approval validation. This blocks durable retry activation; bounded in-attempt provider retry classification can be implemented separately.

Other known boundaries: wall-clock rollback rejects CAS; current host timestamps require a reconciliation policy rather than silently rewriting old evidence. Startup reconciliation and UI retry remain downstream work. No additional blocker is inferred from missing GUI/model acceptance for pure candidate modules.
