# AZ-063 read-only data inventory candidate (2026-10-16)

`scripts/upgrade-data-inventory.mjs` enumerates regular files under an explicitly supplied global config directory and each explicitly supplied project `.agentz` directory. It records a versioned manifest with relative file names, sizes and SHA-256 hashes, a fingerprint of each root path, application version, and whether `config.json` and `.secret_key` are both present. It rejects symlinks, unsupported file types, duplicate roots, over-limit inventories and files that change during hashing. It never prints file contents or raw root paths. A synthetic global config/key/project fixture confirms three files, stable roles, private marker exclusion and hash change detection; `node scripts/upgrade-data-inventory.verify.mjs` passed on Windows.

This is a read-only preflight inventory, **not a backup or recovery path**. It cannot prove a coherent snapshot of live SQLite files, protect a copied config/key pair, restore credentials, validate task/session/environment/artifact binding, or supply the two historical-version migration fixtures. No real user data was inventoried or restored. AZ-063 and M8 remain pending until the versioned protected transaction and recovery checks are implemented and unified acceptance is run.

Preflight follow-up: the manifest now lists SQLite WAL/SHM/journal sidecars and explicitly flags that database copying requires quiescence. Overlapping roots are rejected so the same project state is not inventoried under two roles. The synthetic fixture includes `runs.db-wal` and an overlapping-root rejection; verification passed on Windows. This detects a hazard but does not quiesce writers or make the manifest a consistent snapshot.

Protected bundle candidate: `scripts/upgrade-data-backup.mjs` uses the inventory for an explicitly quiesced **operator-attested** source and requires both `config.json` and `.secret_key`. A passphrase arrives on stdin, derives an AES-256-GCM key with scrypt, and encrypts each file and the manifest before publishing a new bundle directory. `verify` authenticates and hashes every object. `restore-preview` decrypts only into a new review directory, checks the original source-root fingerprints supplied by the operator, and never replaces active application data. Existing output paths, nested source/output paths, changed source files, wrong passphrases and altered objects fail; staging output is removed on failure. A synthetic config/key/project round trip plus wrong-key, wrong-binding, existing-output and ciphertext-tamper cases passed with `node scripts/upgrade-data-backup.verify.mjs` on Windows. No real user state was backed up or restored.

This is still **not AZ-063 acceptance**: the quiescence flag is an assertion, not a host-enforced pause; no coherent live SQLite snapshot, app-integrated transaction, in-place atomic recovery, credential decryption check, task/session/environment/artifact binding check, or two historical-version migration fixtures have run. The bundle format is a local candidate and must not be treated as a release rollback artifact. AZ-063 and M8 remain pending.

Capture hardening: after encrypting all inventoried files, `create` now runs a second bounded inventory and compares the complete roots, names, sizes and hashes before publishing the bundle. A new, removed or changed file aborts publication and deletes the owned staging directory. This narrows an offline capture race but does not replace writer quiescence or an application-coordinated database snapshot. The synthetic backup and inventory checks passed again on Windows.

Portable restore hardening: manifest verification now rejects file names that collide after case folding within one root. A fixture creates an authenticated but malicious manifest containing `config.json` and `CONFIG.JSON`; both verify and restore-preview reject it before a review directory is published. The encrypted synthetic round trip and failure suite, syntax checks and diff check passed on Windows. This narrows a cross-filesystem overwrite path; it does not validate a live app recovery.

Bundle census hardening: verify and restore-preview now require the `objects` directory to be a real directory containing exactly the regular files named by the authenticated manifest. A synthetic bundle with an unlisted extra object is rejected before preview output is published. The encrypted round trip and failure suite passed again on Windows.
