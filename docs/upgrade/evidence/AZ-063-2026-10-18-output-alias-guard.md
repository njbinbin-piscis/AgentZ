# AZ-063 offline backup output alias guard (2026-10-18)

The offline backup and restore-preview candidate now resolves an output's existing parent to its physical path before checking whether the new output would be inside the global config, a project `.agentz` root, or the encrypted bundle. This closes a junction/symlink alias path that previously bypassed the lexical overlap check and could place the staging directory inside protected source data. Both create and restore-preview use the resolved target for staging and publication.

The synthetic Windows round trip now creates a junction alias to the fixture config directory and confirms that both create and restore-preview refuse an output through that alias without creating it. `node scripts/upgrade-data-backup.verify.mjs`, `node --check scripts/upgrade-data-backup.mjs`, and `git -c core.safecrlf=false diff --check` passed. No real user state or native app recovery was tested. This narrows an offline filesystem boundary; it does not enforce writer quiescence, produce a coherent live SQLite snapshot, validate credential/task identity after restore, or satisfy migration and rollback acceptance. AZ-063 remains pending. The selected recovery policy remains restore-to-new-location, not in-place replacement.

The inventory's overlap check also resolves each root's physical path before comparing roots. A Windows junction fixture now proves that a project root aliased through a different parent cannot cause the same state to be inventoried under overlapping roles. Both `node scripts/upgrade-data-inventory.verify.mjs` and the encrypted backup round trip passed after this change. Path fingerprints still identify the operator-supplied lexical roots for restore binding; this check only rejects physical overlap at capture time.

The passphrase reader now stops after 4096 input bytes and clears buffered chunks on success or failure, including a too-short secret. The synthetic suite verifies a 4097-byte input is refused before key derivation. This limits secret buffering for the CLI candidate; it does not change the lack of host-enforced snapshot consistency.

The output existence check now uses `lstat` so a dangling symlink or junction counts as an occupied target and cannot be replaced during publication. The fixture verifies that create and restore-preview refuse a dangling Windows junction while preserving it. Manifest validation also rejects a case-insensitive file/directory ancestor collision before object reads or restore writes; a forged encrypted manifest with `config.json` and `CONFIG.JSON/nested` is refused. The full synthetic encrypted create/verify/restore-preview suite, syntax checks and diff whitespace check passed after these guards. These checks do not address the outstanding snapshot, identity or native recovery requirements.
