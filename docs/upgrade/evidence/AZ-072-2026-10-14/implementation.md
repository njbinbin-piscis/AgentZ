# AZ-072 durable trigger core candidate (2026-10-14)

Added an isolated SQLite trigger/occurrence ledger in `agentz-task-state`. It stores a trigger definition, enable generation, interval, next due time and explicit missed-window policy (`Skip` or `Latest`). A due slot is claimed and the next slot advanced in one immediate transaction; a second connection cannot claim it again. A changed or disabled trigger increments its generation. `begin_dispatch` checks the claim and current generation just before a local dispatcher would run, so a stale claim is rejected after disable. Dispatched and unknown outcomes are not automatically replayed after reopening the database. External side effects would still require the AZ-025 action permit.

Seven deterministic unit tests passed: SQLite reopen/idempotent register without replay, skipped windows, disable-before-dispatch, two-connection duplicate claim, terminal outcome immutability, unresolved in-flight inspection after SQLite reopen, and stable distinct action keys. `finish_dispatch` records succeeded, failed, or unknown only after dispatch begins; a failed or unknown outcome is not automatically retried. `unresolved` lists claimed/dispatched rows for explicit reconciliation without rearming them. Each occurrence yields a stable digest-based AZ-025 action key, but the permit is not yet acquired by a host. The module is a domain candidate only: no host scheduler, actual cron/event source, execution adapter, process restart or sleep integration, external action binding, or user-facing enable/disable control is wired. AZ-072 stays pending; M2/M3/M4/M7 gates remain unmet.

Follow-up review found a scan starvation case: when the oldest due trigger used `Skip`, `claim_due` returned `None` after advancing it, hiding another due trigger from a one-call scheduler scan. It now continues the scan until it finds a claim or no due triggers remain. A negative clock is rejected. The focused suite is now 8/8 passing (`cargo test --manifest-path crates/agentz-task-state/Cargo.toml --offline --locked automation::tests`). This does not add a host scheduler or satisfy restart/sleep acceptance.

A separate-process integration fixture now starts the compiled test binary in a child process, claims the latest slot after a deterministic missed-window clock jump, begins dispatch and exits before completion. A second child cannot claim or dispatch that slot. The parent reopens SQLite, observes one dispatched unresolved occurrence, rejects replay, disables the trigger and verifies another child finds no due claim. `cargo test --manifest-path crates/agentz-task-state/Cargo.toml --offline --locked --test automation_restart` passed (2/2). This verifies process restart behavior and simulated missed windows, not an actual OS sleep/resume or host scheduler.

A bounded host reminder source now exposes main-window verified-scope status, set, disable and poll commands. Users can set one interval reminder per WorkZ task (hour/day/week); the title-bar inbox polls once per minute and on window focus, so reopening a project observes the latest missed due slot. Polling claims at most 25 occurrences, checks generation before local dispatch, and posts only local `ActionRequired` inbox notices keyed by the occurrence's stable action key. A failed notice write records an unknown outcome rather than replaying it. The focused host poll fixture passed after a deterministic clock jump, duplicate poll and disable. This is an intentionally limited **reminder** path: it does not run a model or execute external actions, and has not been exercised through a native desktop journey. AZ-025 permit binding and full task automation remain unimplemented.

Validation for this host/UI batch: targeted desktop unit test 1/1, frontend reminder client tests 2/2, `npm run typecheck`, and `npm run build` passed. The production build emitted an existing chunking warning; no native desktop journey was run. Projectless managed directories are excluded from the reminder control because the title-bar poll currently follows the selected repository project scope.

Final source review tightened scope-change handling in the reminder controls and title-bar inbox: renderer state follows scope acquisition and revocation, and stale asynchronous responses from a previous project are ignored. The host poll returns the number of notices actually inserted. The targeted desktop reminder test passed after that host change (1/1); frontend typecheck and a final production build passed after the renderer change. This does not substitute for native desktop acceptance.
