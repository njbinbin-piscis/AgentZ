# AZ036 next actionable slice: task-scoped read-only IDE adapters

Read-only inventory and implementation contract, 2026-10-09. No product/manifest/ledger edits or test runs here. Current task_view descriptor is observational only; supplying its workspace_root to existing IDE commands does not make those commands task-authorized.

## Existing command boundary

commands/ide.rs ide_list_files accepts renderer project_dir and walks tree in spawn_blocking; depth defaults10, no task/session scope or total-node cap. ide_read_file accepts absolute path plus unused State and uses bounded_read maximum10MiB, returning FileContent with binary/image preview handling. Neither performs task-view authority validation. Write/file_action/search/Git mutation commands likewise use paths. Remote branches now bind authority/generation, but they do not establish local task identity. ide_terminal_create accepts project_dir/cwd and creates process state; terminal write/resize/destroy/read use terminal ID. commands/dap.rs dap_start/dap_send/dap_stop use global adapter state; commands/browser.rs navigation/click/scroll use global browser state and external URL. They cannot be called a same-task capability merely by changing React projectDir.

Existing reusable authority is commands/chat_plan.rs existing_binding plus session_metadata and project_scope helpers, environment_access.execution lease and task_view resolver's fresh scope comparison. TaskActivityGate excludes queued/running/intent mutation of the same canonical project/task; it does not turn arbitrary filesystem paths into authorized ones. Approval resolve_binding and broker are exact-action execution contracts, not a generic read-path grant. Avoid registering fake Run/Attempt just to open a file.

## Recommended next slice without a new opaque capability registry

Implement **two dedicated read commands**, task_view_list(scope_handle,session_id,expected_binding) and task_view_read(scope_handle,session_id,expected_binding,relative_path). expected_binding is a stale-view assertion only, never authority: host re-resolves existing binding/workspace on each call and requires equality. Both derive workspace from registered environment/existing metadata using the same trusted resolver, and revalidate main-window opened scope after awaits. No renderer project/workspace/absolute file path input. Original authority project and session stay unchanged. The existing project scope handle is sufficient for this small readonly slice; minting a task-view handle adds expiry/revocation state without eliminating fresh per-operation checks.

Refactor only task_view.rs internals into a shared captured-context helper within that owned module, or add commands/task_view_read.rs importing a crate-private helper; root owns mod/lib registration. Helper carries metadata/env/fresh PlanBinding plus host-resolved canonical root; never expose operational access via the DTO. Hold the environment lease through actual read. Main scope registry guard must cover authorization and captured root use; do not drop it then start a detached read which can outlive revocation. For bounded synchronous read/list use same guard as existing task_details; document contention cost. If spawn_blocking is needed, introduce a revocation-aware lease before releasing registry mutex, rather than moving authority outside the guard.

Path policy: nonempty bounded workspace-relative normal components only; reject absolute/drive/UNC, '..', '.', NUL/control and remote schemes on every platform, including Windows backslash and drive-prefix forms. Existing nonexistent targets fail. Reject symlinks/reparse traversal outside root, do not normalize a malicious path into acceptance. Canonical prefix checks alone have a check/open race; production read should open then verify actual handle-final path belongs to the captured root (Windows final-path API, POSIX nofollow/component walk), and bounded-read from that same handle. If that cannot be delivered safely in one slice, conservatively reject symlink/reparse trees and explicitly defer hostile external replacement guarantees; do not claim filesystem capability isolation from lexical checks alone.

Use independent readonly DTO initially: TaskFile {relative_path,encoding:utf-8|binary,content:string|null,size,binding}, no absolute file authority or executable HTML/SVG. Maximum1MiB retained text/read bound, binary returns explicit unsupported preview rather than raw base64. List maximum depth3/nodes1000 with explicit truncated flag and relative nodes; avoid forwarding unbounded ide_list_files. Do not execute Git, watch, LSP, terminal, browser or DAP. These new adapters can support a small same-task readonly file viewer while existing full IDE remains disabled for that route.
