# AZ043 owned debug-controller candidate

2026-10-10. Implemented only debugController.ts, its new tests and root-authorized small debugStore.ts changes. No host/client files, ledger, production build, Cargo, real adapter or GUI touched by this author.

Controller exports a class with optional createClient/projectDir/initializedTimeoutMs/stopTimeoutMs/registerWindowListener dependencies. DebugClient contract preserves connect, generic request, onEvent/onLog and async dispose; production singleton still uses DapClient and the existing window launch event. Every start captures a deep config snapshot and project/remote identity before its first await, synchronously detaches the preceding session and acquires an epoch. Each later continuation/event operates on its captured client/session and checks ownership; an old connect failure/EOF/output or handshake completion cannot stop or overwrite the replacement session. Explicit stop revokes ownership and ends visible debug state before bounded best-effort disconnect/dispose; this is not proof the debuggee/remote process exited.

The handshake requires a real initialized event within the deadline; successful launch response alone does not satisfy it. initialize capability supportsConfigurationDoneRequest=true enables configurationDone, otherwise the unsupported request is omitted. SetBreakpoints/configuration failures are surfaced and terminate that owned candidate rather than swallowed. Breakpoint snapshot filters outside captured lexical project root and reserved recovery paths; this filter is not canonical filesystem authorization or a host scope grant. The existing placeholder node adapter default remains a placeholder, not a verified js-debug installation.

Pause revisions own stack/scopes/variables queries. New stopped events clear old variables immediately; continued or another pause invalidates earlier queries at every await. Step retains paused state until a successful current response (or real continued event), surfaces failures and has synchronous single-request ownership for same-tick clicks. A new stopped event cannot be overwritten by completion of a preceding step. debugStore running=true now clears thread/frame/variable projection, new stopped clears variables, and start allocates fresh output/frame/variable arrays rather than mutating EMPTY arrays across sessions. Source search confirms only this controller calls these debugStore running/stopped methods; extensionUiStore's unrelated running API is unchanged.
