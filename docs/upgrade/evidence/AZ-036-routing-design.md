# AZ036 minimal task routing design

Read-only investigation, 2026-10-09. No product/build/ledger changes. This is an implementation proposal, not GUI or routing acceptance.

## Existing entrances and concrete risks

WorkzSidebar.tsx onOpenInCodeZ currently passes a project path, not a task/session. workz/index.tsx forwards this callback; App.tsx openProjectInCodeZ calls switchProject(dir) then unconditionally setMode(codez). switchProject has navigation-busy and active-terminal confirmation, workspace persistence and previous-scope revocation. It returns false on rejection, but openProjectInCodeZ currently ignores that result. This is a concrete navigation correctness fix for the next implementation slice: cancelled/busy/failed switching must not claim successful routing or change mode.

CodeZWorkspace currently receives projectDir as both editor/tree/watcher/terminal/debug/preview root. Its projectDir change effect clears tabs. Dirty-buffer persistence/hot-exit exists, and close-tab/all paths have save prompts, but the project-change effect itself is not a dirty-buffer guard. App switchProject persists workspace before clearing; persistence is not user consent to discard live buffers. Reusing this path with a managed worktree root would also revoke original project scope, move the session database identity, and select a different CodeZ history. It is therefore not same-task navigation.

AssistantPanel maintains sessionRef and last-session storage by projectDir, resets on project change and emits ordinary CodeZ source turns. App's IdeSidePanel receives original projectDir only; there is no task-navigation session prop in the present route. CodeZ cannot silently pick a WorkZ task merely by receiving its workspace directory. WorkZ's current sidebar project action should remain project navigation; add a separate explicit task-open action using the existing selected session and trusted project scope.

## Minimal coherent context

Keep two roots distinct in an immutable host-issued task view context: authority project (canonical original project/session database), session/task ID and environment/binding version; execution workspace (verified environment workspace_root or direct resolved root); opaque project scope handle plus opaque task-view handle/revision. Editor/terminal/debug/preview roots come only from a freshly validated host task-view resolver, not from frontend TaskDetails Source::Available. AZ035 is observational data and cannot authorize opening any returned path.

New narrow host command should use existing_binding and the existing metadata/scope helpers: main-window opaque scope lookup, existing supported session, environment execution lease, awaited workspace resolution, then with_verified_scope recheck before issuing bounded local task-view descriptor. Registered environment authoritative; direct/free single-agent metadata and host-restored source rules as existing binding. Reject team/pool/remote/background in first slice. Bind descriptor to project/task/environment/binding version; later IDE actions must revalidate it or use existing validated task-bound host routes, not trust renderer workspace strings.

Do not mint a new direct task, ensure-session or Run during navigation. Do not change original projectDir to workspace_root. First slice may route editor read access with passive task summary while explicitly disabling task-bound Send/terminal/debug actions until their host authorization adapters exist; this is safer than allowing an unrelated AssistantPanel session to look like the same task. Full same-task continuation needs an explicit captured session prop/source in AssistantPanel and turn host validation accepting that existing WorkZ session. Ordinary CodeZ session selection must not overwrite it by a project last-session effect. Reusing an existing session requires its original source/channel; do not relabel WorkZ as CodeZ automatically.

## Proposed small implementation batches/files

1. App.tsx: honor switchProject result immediately; introduce separate task route state and navigation serial/generation, keeping original project identity. Workz index.tsx adds selected single-task open callback (separate from WorkzSidebar project callback). New pure taskViewRouting.ts reducer/fixtures validates descriptor and late-request identity without granting authority.
2. New commands/task_view.rs plus small mod/lib registrations: narrow fresh existing-session resolver and opaque task-view capability registration/revocation. Reuse commands/chat_plan.rs existing_binding, session_metadata.rs and runtime/project_scope.rs; avoid copying authority logic. No renderer workspace argument.
3. CodeZ index.tsx: separate filesystem workspace prop from authority project/task context. Keep IDE watcher, tree, file, terminal, debugger and preview actions on the verified workspace through task-view host adapters. App/IdeSidePanel/AssistantPanel explicit selected task context only after existing-session/source support is audited. Product implementation must enumerate all projectDir consumers before enabling writes/execution.
4. CodeZ buffer guard: expose a real async prepare-navigation gate from live editor state (save/keep snapshot/cancel), await it before descriptor/root commit. Reuse existing terminal close confirmation/destroyAllTerminals; invoke also on workspace change within the same original project (current same-project short circuit would otherwise skip it). Recheck navigation generation after awaits, and do not revoke old scope/destroy editor state until all gates succeed. Failed save or cancelled terminal retains original context.

Native terminal/debug/process actions cannot be guarded solely by changing React props. Existing task-gate/environment lease prevents cleanup races but does not prove all terminals belong to the task; adapt creation and cleanup ownership explicitly. No whole-App architecture rewrite is required, but editor root and session authority must be split together at the route boundary.

## Executable fixture plan and completion criteria

Pure routing fixtures: managed workspace differs from authority project yet session/task preserved; direct/free resolved route; wrong scope/environment/old descriptor rejected; later response cannot overwrite newer route. App behavior fixtures: switchProject false does not change mode; cancelled buffer save/terminal confirmation leaves route intact; same authority/new workspace still invokes both gates; failed persistence or revoked descriptor never resets tabs. Assistant continuation fixture must prove invoke retains original project/session/source and does not create a new task. Host real temporary SQLite/environment fixtures: missing session rejects/no ensure, managed source authority wins over renderer path, descriptor resolution does not create Run/database, scope revoked after await rejected, team/remote unsupported.

Completion of a first passive slice is narrower than full AZ036: task identity and readonly filesystem inspection can be tested without granting terminal/debug/send authority. Full acceptance needs native dirty editor + active terminal + managed worktree same-task roundtrip and GUI task switch; these have not run. No publication/build or new task execution was performed in this design review.
