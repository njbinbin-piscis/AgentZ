# AZ-073 persisted inbox domain candidate (2026-10-14)

Added an isolated SQLite inbox in `agentz-task-state` with four explicit meaningful notice kinds, durable event-key deduplication, task IDs for later navigation, bounded summaries, recent listing, unread count, and idempotent mark-read. Reposting the same event after SQLite reopen preserves its read state; reusing its key with a changed payload fails. Two deterministic unit tests pass (reopen/read-state/conflict and two-connection deduplication).

The Tauri host now exposes main-window, verified-project-scope list and mark-read commands. Read timestamps come from the host clock; renderer code cannot insert notifications. A bound Run's durable terminal transition posts completion, failure or interruption to the inbox using its persisted timestamp and task identity. Inbox failure is logged after the Run commits and does not retroactively change the Run result. `cargo check --manifest-path src-tauri/Cargo.toml --offline --locked` passed for the scoped commands, and the targeted desktop `ManagedRun` test passed with the bound-run completion notice assertion.

The frontend now validates the host inbox response, shows a project-scoped title-bar inbox, refreshes it on open, marks a selected notice read, and routes its task ID through WorkZ's existing session-opening path. Project changes clear the visible inbox. Two focused client tests and `npm run typecheck` passed.

This remains an implementation candidate. Trigger, approval and other meaningful-change sources are not connected; no native click-to-task or product-level unchanged-state quiet journey has been exercised. AZ-073 remains deferred; AZ-072 and unified acceptance are incomplete.

Follow-up review fixed inbox navigation ordering: selecting a notice now opens its task immediately and persists read state afterward. A failed read-state write no longer blocks task navigation; the error remains visible when the project is still current. `npm run typecheck` passed. This is a source-level correction, not native click-to-task acceptance.

The inbox domain now has an atomic semantic-state quiet policy. `post_change` stores the latest fingerprint for a stable source key and inserts a `meaningful_change` notice only when that state changes; polling the same state remains quiet across SQLite reopen. A changed state must use a fresh event key, so an old notice cannot silently advance the source state. The focused inbox suite passed (3/3), including unchanged polls, reopen and A→B→C transitions. No host trigger/approval source calls this API yet, so product-level quietness remains unverified.

The source state also binds to one task ID. Reusing a source key for a different task fails rather than suppressing that task's notice; the same focused suite passed after this check.

The protected approval hook now posts an `ActionRequired` notice using its host-issued immutable request ID and bound task ID when an interactive approval becomes pending. When that request receives a decision or times out, the hook marks its notice read so an already resolved approval does not remain in the unread count. Posting and resolution failures are logged without changing the approval decision. The existing host `exact_approval_is_claimed_before_execution_and_finished_by_actual_tool_id` integration fixture now checks the persisted notice identity and its unread-to-read transition; the targeted desktop test passed after a final-source rebuild. This is an approval event-source candidate, not a native inbox navigation or restart-expiry acceptance test.

The local reminder path now supplies another meaningful inbox source: a due interval claim posts one `ActionRequired` notice with its durable occurrence key. Repeated polls and a disable-before-next-slot fixture do not add notices. WorkZ exposes hour/day/week reminder controls for repository tasks and labels the capability as an inbox reminder that does not run the task; the title bar polls while the project is open and after focus. The host poll test and two scoped frontend-client tests pass, as does frontend typecheck. Native reminder click-through and actual process restart/sleep product journeys remain untested. Projectless managed directories are excluded from the reminder control until their distinct scope can be polled safely.

The production frontend build also passed after this wiring. No native visual or click-through result is inferred from that build.

Final source review added scope acquisition/revocation refresh and ignored stale asynchronous inbox results after a project change. Frontend typecheck and a final production build passed after the change; native inbox navigation remains unverified.

The scoped inbox read now reconciles unread host-issued approval notices against the durable approval ledger. Opening the ledger under the current process boot expires prior-process pending approvals; denied, expired and other non-pending requests are marked read, as are same-boot requests past their expiry. This prevents a stale action-required badge from claiming an approval is still actionable after restart or timeout. Reconciliation is bounded to the 100 most recent notices and logs approval-store errors without hiding the inbox. `cargo check --offline --locked` and the focused host fixture passed (1/1), covering live, same-boot expired, denied and previous-boot cases. This is not a native restart/approval journey.

The follow-up query now selects up to 1,000 unread approval candidates separately from the visible 100-notice page. A fixture inserts 101 newer unrelated notices and still reconciles the older expired, denied and previous-boot approval notices; targeted host test 1/1 and inbox domain tests 3/3 pass. The 1,000-candidate bound remains a documented backlog limit, not an unbounded scan.

Backlog follow-up: approval reconciliation now rotates through unread candidate keys in durable pages of at most 1,000. The cursor survives reopening `inbox.db`; when a page reaches the end it wraps, so a full page of still-live approvals cannot starve a later stale notice forever. A 1,001-notice domain fixture checks pagination/reopen/wrap, and a host fixture checks an expired notice after 1,000 earlier candidates is marked read on the next reconciliation. Four inbox domain tests and two host reconciliation tests pass. Each inbox read still does bounded work; a backlog may need multiple reads before all stale notices are cleared. This does not substitute for native restart or click-through acceptance.
