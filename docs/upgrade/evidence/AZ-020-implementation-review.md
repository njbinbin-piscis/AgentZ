# AZ-020 independent implementation review for AZ-035

Reviewer: Codex subagent parallel_plan, independent of root's ledger acceptance. Scope: current durable Plan DTO/read semantics and host query boundaries, solely as an implementation dependency for AZ-035. This does not satisfy the formal AZ-020 acceptance Gate. Source hashes are in AZ-020-implementation-manifest.json; any source change requires renewed review/pinning.

The current contract is suitable for consuming an already authoritative Plan result: PlanBinding contains canonical project, task, environment and binding version, without per-turn Run/Attempt identity or execution authority. continue_plan requires exact fresh binding and retains stable plan ID/revision, objective, full items and closed status. Missing current head is None; bad records, stale environment/binding and malformed status/timestamps are errors, not an empty plan. Done and Cancelled item states remain distinct; a nonempty list with no open item is Completed. Whole-plan cancellation is explicit and does not cancel a Run.

PlanQuery preserves Completed/Cancelled current records and their full items. AZ-035 must consume this persisted DTO, not DurablePlanSession.projection: the execution projection intentionally empties Cancelled/Replaced items. It must not derive a new goal or clear the plan from ordinary continuation, a new Run ID, or an empty runtime cache. Explicit mutations use ID/revision CAS plus same-task gate and active/queued Run validation. A DTO is neither authorization nor a permission grant.

Important read limitation: PlanStore::open creates .agentz/plans.db and initializes schema version zero inside an Immediate transaction. chat_plan_query currently calls this initializer. Thus passive task-detail discovery must NOT use this opener while claiming read-only/no-create behavior. AZ-035 may first implement a pure aggregation module over validated repository results; a subsequent separately reviewed existing-readonly PlanStore opener is required for mutation-free SQLite discovery. continue_plan itself does not write, but that does not make open+query read-only. Existing schema validation covers query shape and record integrity, not exhaustive SQL PK/NOTNULL layout inspection; serde does not reject every unknown JSON field. Do not claim those stronger guarantees.

The host query uses an opaque host project scope, existing session/source validation, metadata-only fresh binding and retained environment lease. Single-agent local CodeZ/WorkZ are supported; team/pool/remote/background and unregistered external free cwd remain unsupported. Fresh resolver/lease requirements remain caller responsibilities. Plans, Runs, environment registration and conversation databases do not share one transaction; AZ-035 must report independently obtained versions/status and explicit stale/unavailable errors, not claim an atomic cross-database snapshot.
