# AZ-016 合并事务实现约束（准备稿）

2026-10-05，Asia/Shanghai。下一项的实现准备，尚未开始代码交付/验收；不代表这些保护已生效。

当前入口 `agent_task_merge` 只接受 branch/base，先 checkout base，再 merge；失败吞掉 abort/恢复分支错误。需要替换成按持久 taskId、明确本地目标分支和冻结源/目标 HEAD 授权的事务。

拟定行为：

1. 按真实 Git common-dir 获取仓库互斥，在队列出队时重新验证；执行/归档租约阻止活动或排队中的 Agent 与目录事务冲突。
2. 加载任务登记，核对 task 分支、路径、worktree 归属与评审时的 task HEAD。主目录必须已经在指定本地目标分支，禁止为了合并而隐式 checkout。detached HEAD、SHA 作为目标、别人的 task 分支均拒绝。
3. 主目录与任务目录不能有影响交付的 staged/unstaged/untracked 源码，不能已有 MERGE/REBASE/CHERRY_PICK 等操作。未跟踪运行时目录按既定域规则排除；被 Git 跟踪的运行时修改仍要阻止覆盖。
4. 冻结目标 HEAD，验证冲突预检不改变用户 index/工作区。评审源或目标漂移时要求刷新，不自动接受新版本。明确 Git 版本不支持预检时的错误，禁止把失败当作“无冲突”。
5. 合并前保存恢复依据和源快照；成功返回目标原/新 HEAD、合并任务版本与事务标识。分支仍保留。任务创建时的本地源码起点包含在正常 Git 祖先关系中。
6. 合并失败必须报告具体阶段与磁盘实际状态。仅当当前状态证明是本事务产生且没有后来编辑时才尝试 abort；abort 再失败必须返回，不能吞掉。存在外部修改或归属不明时保留现场与恢复路径，不 reset --hard、不强删。

验证场景：两个同仓库合并请求串行并重验；主目录 dirty/staged/untracked 拒绝且字节/index 不变；源目录 dirty 拒绝；错任务/错目标/HEAD 漂移拒绝；冲突在 mutation 前发现；提交 hook/abort 故障如实保留现场；成功合并的父对象和结果内容核对；非同仓库任务不共用身份。

前端应在完整变更集保存 task HEAD，点击合并先得到并使用目标 HEAD 的预检结果，再提交带版本的事务。IPC 不能仅相信按钮禁用或客户端分支字符串。legacy 缺少 task 身份/评审版本时明确拒绝，不能回退到旧 checkout 合并。
