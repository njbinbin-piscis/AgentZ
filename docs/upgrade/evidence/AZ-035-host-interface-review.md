# AZ-035 host interface independent review

Read-only review by parallel_plan of chat_events::chat_task_details, runtime::task_details::read, existing_binding/project_scope helpers and lib/runtime registrations. No source/ledger changes or Cargo execution. Parent27341 four host SQLite fixtures were still compiling/running when assigned; this review does not claim their result.

No new blocking authority/read-integrity finding in this scoped candidate. chat_task_details accepts only scope_handle/session_id, no renderer project or workspace path. It retains the execution environment lease before main-window scope lookup, validates an existing supported session via metadata-only fresh binding, then revalidates that scope under the registry mutex through synchronous reads. Revocation cannot interleave during the callback. Registration includes the command in lib.rs and task_details module export. It does not queue/start Runs, grant approval capabilities or execute tools/model work.

The service canonical-checks project/binding, loads existing environment readonly, allows absent registration only for matching direct fingerprint, and validates registered environment identity. Run discovery and budget read use existing readonly connections with no initialization; plan uses the newly reviewed readonly opener. Missing files/head/policy are Missing, schema/record corruption and I/O failures propagate Err rather than zero/empty state. File existence checks are advisory only: subsequent noCREATE open errors if a source disappears, preserving the no-mutation boundary. Cancelled plans return full items and revision, not the empty execution projection. Events remain Unknown and artifacts Unsupported; neither reference is fabricated.

Candidate limitations are explicit: atomic_snapshot=false and per-source versions do not establish one cross-database transaction. A concurrent plan/Run update can occur between observations because no execution task lock is taken for these passive reads. Error paths currently fail the complete query rather than return per-source Unavailable/Stale DTO; this is an explicit error, not silent fallback, but full roadmap stale-source presentation remains unfinished. Budget Snapshot is observational, not reservation/enforcement state; unknown price/tokens remain unknown. Source version labels such as run-v1:timestamp or plan-v1:revision must be interpreted with value identity, not used alone as global cache keys. The reader is not an environment freshness proof against external filesystem/process changes.

Synchronous SQLite validation runs while the project-scope std mutex is held, with up-to-five-second busy timeouts per store; this preserves revocation exclusion but can delay scope management under contention. Keep it as a measured bounded follow-up rather than moving reads outside the scope guard without an equivalent capability recheck. Native IPC/window fixtures, dual-view UI consumption, model/GUI timing and cross-platform acceptance have not been run here. AZ-035 remains implementation candidate, not formal Gate complete.
