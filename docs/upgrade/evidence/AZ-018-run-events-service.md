# AZ-018 passive lifecycle event page service candidate

2026-10-08. Exclusive new frontend service `src/services/tauri/runEvents.ts` and its test file. DTOs were coordinated with the runtime replay agent and checked against the implemented `chat_run_events`/PageDto source. No UI wiring, model resumption, host build, publishing or ledger change.

`readRunEvents(scopeHandle, sessionId, runId, attemptId, cursor = null, limit = 200)` invokes only `chat_run_events` with these camelCase parameters. Stream/Cursor/Event/Page interfaces retain the Rust snake_case fields. The page includes stream, events, nullable next_cursor and has_more. Requests reject invalid identities, unsafe cursors, cross-request task/run/attempt cursors and limits outside 1..200. Returned stream must match the requested identity and the cursor's environment where present. The response is validated as a bounded event page before returning; authorization failures propagate without fallback or another invocation.

`RunEventCollector` is a pure bounded reducer. Its stream and optional starting cursor are fixed at construction. It validates every event's stream/sequence/stable identity/kind/timestamp/JSON payload, ordered pages and contiguous new sequence. Exact previously known events deduplicate, including structurally equal JSON payloads; a changed ID at the same sequence, the same ID at another sequence or changed record content rejects. The next cursor must equal the final event cursor (or the previous cursor for an empty page). A has_more page must advance. A fixed page budget prevents endless repeated replay; rejected pages leave collector state unchanged. Snapshots and cursors are defensive copies, so consumer mutation cannot corrupt dedup state.

Legacy empty history stays empty. A collector initialized after sequence N accepts N+1 onward without inventing earlier capture. This is passive lifecycle display, not execution reconstruction, automatic continuation or side-effect replay. The caller remains responsible for obtaining an authorized project handle and deciding whether UI state still refers to this task when an async result returns.

Added six tests covering exact IPC payload, request limit/cursor rejection before invoke, response attempt/environment mismatch, overlapping exact replay, defensive snapshots, sequence gaps/order regression/stable-ID and payload conflicts, page atomicity, cross-stream records, oversized pages, invalid next cursor, nonadvancing has_more, bounded total pages and empty legacy history.
