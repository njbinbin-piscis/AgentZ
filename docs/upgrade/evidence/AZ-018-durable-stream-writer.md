# AZ-018 captured stream writer candidate

`runtime/durable_stream.rs` provides `DurableStreamWriter::open(project, binding)`, `record(payload) -> Event` and `record_before_publish(payload, callback) -> Event`. The caller supplies the real early host Run/Attempt binding, not a renderer identity or metadata-only resolver UUID. Open verifies the canonical project, requires an already-existing Run database with `try_exists`, and checks captured task/environment/current attempt against that Run. It never calls Run creation. Root changed opening to `RunStore::open_existing_readwrite`, which has no CREATE flag or schema migration; deletion between inspection and opening cannot recreate a database. The caller retains the existing environment lease against in-process destructive cleanup. This is not a cross-process deletion lock.

Each received event obtains one bare UUID, captured with the single append invocation, and a checked nonnegative millisecond clock. The separately implemented `RunStore::append_agent_event(binding, event_id, payload, now)` prefixes `agent.` and returns the committed Event unchanged. There is no retry or fabricated cursor on failure. Store-level enforcement of current matching Running attempt, exact binding and 1 MiB payload is a dependency of this candidate. `record_before_publish` executes its callback only after successful record, and returns the persisted Event. Root owns collector integration and explicit persistence-failure handling.

Four real SQLite fixtures are authored: Running direct Run -> record -> reopen readonly and replay the exact returned payload/UUID/cursor; missing database leaves `.agentz` absent and wrong captured identities reject; oversized, terminal and stale-after-retry records reject; the publish callback opens a separate readonly connection and observes the exact committed event, while oversized and terminal failures never invoke it. These tests are not run by this agent. Scoped rustfmt exited 0. No Cargo, model, GUI or ledger edits were performed.

Open also rejects Queued/terminal Runs and requires `Running` plus `NotReady` delivery before model startup. The existing missing/wrong-binding fixture additionally covers Queued and terminal constructor rejection. Record retains transactional current-attempt checks for changes after opening.
