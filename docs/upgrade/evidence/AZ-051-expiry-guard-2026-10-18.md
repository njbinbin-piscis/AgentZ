# AZ-051 OAuth expiry fail-closed guard (2026-10-18)

The desktop host now treats a malformed stored `expires_at` as expired. An explicit provider `expires_in` of zero or less also expires immediately; only an absent `expires_in` represents a provider that did not declare an expiry. Calculating a positive expiry uses checked arithmetic, so an out-of-range response cannot turn an access token into an undated token or replace previously stored credentials.

The loopback callback listener now rejects unrelated local requests or a mismatched state and keeps waiting for the authorized redirect within its existing overall deadline. A local fake-token-endpoint test sends the wrong state first, then a valid callback, and confirms that only the valid authorization code reaches the token endpoint.

The focused OAuth tests cover malformed and extreme stored expiry values, zero lifetime, overflow preserving the previous token, and callback recovery. This is a local candidate; the broader AZ-051 flow still needs independent review, actual provider authorization/refresh/revoke receipts, and integration of live tool revocation. No external account was used.

Registered connector MCP tools now check the current manifest, authorization, expiry and resolved transport configuration before each call. A changed credential cannot reuse the MCP client that still holds the old token. The check is installed in chat turns, Koi turns and gateway turns. Disabling an OAuth connector also prevents agent-selected registration even if the agent had explicitly selected it; uninstalling removes the manifest and denies the old tool. This protects calls begun after revocation; it does not cancel a call already in flight.

Disabling or uninstalling a connector now aborts any pending OAuth callback task and waits for it to stop before clearing credentials or deleting the connector. A local async fixture verifies that aborting an already running pending task prevents its delayed token work. Authorization started later by a separate user action remains a distinct attempt; a real native disable/callback race is still unverified.

Verification on Windows: `cargo test -p agentz-desktop --lib connector_guard_tests --locked --offline` passed 1/1 on the final guard source, covering token change, disable, missing credentials and uninstall. `cargo test -p agentz-desktop --lib oauth_ --locked --offline` passed 22/22, including pending-attempt abort. `rustfmt --check --edition 2021` for the four changed Rust files and `git -c core.safecrlf=false diff --check` passed. Two interim compiles failed during implementation (a missing callback `return` and an unavailable test-only `tempfile` crate); both were fixed before the final passing runs. No live MCP server or external provider was invoked.

The current desktop crate also passed `cargo check -p agentz-desktop --locked --offline` on Windows after those changes (dev profile, exit 0). This is a source build check, not a native desktop journey.

OAuth lifecycle transitions now share a local async lock across authorization start, callback token persistence, refresh commit, disable, uninstall and manual credential save. Refresh refuses disabled connectors and checks that the connector is still enabled, has the same manifest identity and retains the same refresh token after the network response, before writing. This prevents a refresh already on the network from restoring credentials after a completed disable or uninstall in this process. A stale-refresh fixture verifies refusal after disable, token replacement and manifest identity replacement. The final source passed `cargo test -p agentz-desktop --lib oauth_ --locked --offline` (23/23), Rust formatting and diff checks on Windows. A concurrent native command/callback fixture and cross-process coordination are still absent; provider-side revocation and already in-flight MCP calls remain open.

The complete desktop library test suite passed after that lifecycle change: `cargo test -p agentz-desktop --lib --locked --offline` ran 367 tests on Windows, with 360 passed, 7 ignored and none failed.

The callback listener now reads the complete first HTTP request line with an 8192-byte bound and per-read deadline. TCP can split a valid redirect mid-parameter; the previous single read could reject it. A split-request fixture now sends `state` in two writes and receives a successful exchange, while an oversized-line fixture is refused. The final source passed 24/24 focused OAuth tests and 361/361 desktop library tests (7 ignored) on Windows, plus targeted Rust formatting and diff checks. The ignored cases and lack of a native OAuth journey remain separate acceptance gaps.
