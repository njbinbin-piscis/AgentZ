# AZ-022 versioned tool/process recovery contract candidate

Owned changes: new piscis-kernel/src/tool_recovery.rs in standalone source and AgentZ vendor, identical bytes; no lib export, runner, shell/code_run, ledger or manifest edits here. Only rustfmt executed, no Cargo/model/GUI/Windows process acceptance. Parent owns consumer integration and unique build/tests. No AGENTS.md was found in the checked source/vendor inventories.

RecoveryReport version1 keeps operation_id, primary Outcome (Completed/ToolFailed/TimedOut/Cancelled/ElevationNoResponse/ElevationDenied/ElevationUnsupported/SetupFailed/WorkerFailed), optional observed exit code, Termination (Unknown/NotStarted/Exited/TreeTerminated), cleanup evidence for both pipe drains and restored access, raw-byte OutputCapture and separate presentation omissions. Truncation does not replace timeout/cancellation. No commands/arguments/output/raw errors/paths/secrets are copied into report metadata. The operation ID must be host-generated; the report is not scope authorization and is not trusted if supplied by renderer/model.

AutomaticRetry has only Forbidden. next_step is NotRequired only for confirmed successful resources and complete untrimmed output; otherwise ReviewOutput for incomplete successful output or ManualReconcile for uncertain/failed/cancelled execution. Neither decision grants replay permission. Root Exited never proves tree termination. A regular Err becomes WorkerFailed + all Unknown, not evidence of no launch or cleanup. UAC lack-of-response/denial exist as explicit future typed observations; error-string parsing is forbidden. refused_elevation_before_launch is ElevationUnsupported, not a claim an actual UAC prompt was denied.

Actual API:

- RecoveryReport::confirmed_result(operation_id:String, exit_code:i32, timed_out:bool, cancelled:bool, stdout_total_bytes:u64, stdout_retained_bytes:u64, stderr_total_bytes:u64, stderr_retained_bytes:u64)->Result<Self,String>. Use ONLY after the trusted runner confirms process tree ended, both pipe threads joined and access restoration returned. Contradictory flags/counts reject. Complete raw capture implies total==retained; Truncated records observed total>retained, including retained0.
- unknown_failure(operation_id) / unclassified_error(operation_id) preserve unknown termination/cleanup; refused_before_launch is valid only before any launch/resource setup, with NotStarted/NotApplicable. Setup failures after ACL/job setup cannot use this constructor.
- note_presentation_truncation(&mut self, stdout_bool, stderr_bool) ORs two serde-default flags. Outer smart truncation/collapse can omit displayed content even when raw capture was complete. Counts remain raw pipe bytes, never lossy UTF8/marker-containing string lengths. Omission flags affect ReviewOutput without fabricating display byte counts.
- attach(self, ToolResult)->Result<ToolResult,String> validates and appends fixed [recovery_v1] JSON [/recovery_v1] footer through the current content/event channel, preserves content/meta/image and forces is_error for nonCompleted outcomes. It does not change ToolResult/ToolMeta layout. This is passive metadata; do not parse the footer as automatic execution authority. Existing arbitrary tool content can contain similar text, so future consumers need trusted provenance rather than trusting text markers alone.
- validate/resources_confirmed/next_step revalidate version, identity, exit/termination/output consistency. Serde rejects unknown fields and unknown retry policy; parse callers must also validate version and semantic consistency, not just deserialize.

Eight inline fixtures cover complete/nonzero/timeout/cancel distinction and roundtrip, plain Err/root-only exit/cleanup failure, UAC observations with no inferred proof, output truncation and invalid counts, unknown version/identity/exit/retry, runner constructor+footer and retained raw counts, explicit unsupported elevation/preflight refusal, monotonic presentation omission and old-v1 fields defaulting. They have not been run by this agent. No automatic side effect replay, receipt finalization, owner proof, budget release or real Windows cleanup is claimed by the contract alone.
