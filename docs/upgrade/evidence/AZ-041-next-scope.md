## Concrete current risks

CodeZ index.tsx scheduleTabReload around line491 removes a deleted backing file tab immediately, including unsaved content. Modified dirty tab prompts reload/discard, then marks clean before the deferred disk read succeeds. The asynchronous reload applies by relative path only; it does not match captured workspace generation or local editor revision. New input while the read is pending, or another project with the same relative path, can receive stale content. reloadTabFromDisk has the same late-reply overwrite boundary and silently ignores errors. saveFile around line748 writes captured content then clears dirty by path regardless of later typing; newer unsaved edits can be marked clean. These are concrete correctness gaps, not hypothetical GUI findings. No code is changed during the build freeze.

The watcher FileChangedEvent currently contains project_dir/path/kind only, no authoritative content revision/hash. FileContent contains actual bounded content/encoding/size but no expected-base token. OpenTab keeps content/isDirty without a separately retained original disk content/hash/editor revision. Existing global workspace snapshot stores only current dirty buffers and is overwritten by later saves; it does not retain a cross-project conflict history or base version. Artifact snapshots now retain versions but are user-captured outputs, not automatically proven editor disk bases. Git status/unmerged markers do not solve unsaved editor vs external-write conflicts.

## Small implementation order

1. **Preserve local state first.** Add pure conflict state/reducer with scope generation, tab identity, monotonic local revision, retained base text/hash, observed remote text/hash or explicit deleted/unavailable. Watcher events are invalidation hints, never permission to discard. Dirty deletion retains a recoverable tab with disk-deleted status; failures leave contents/dirty state unchanged. Async replies require matching scope/tab/request/local revision. Dirty edits remain dirty after an older save finishes. Clean reload only applies if local revision still matches capture. Do not ask the user to discard then clear dirty before successful read.

2. **Expose explicit comparison/decisions.** Add small conflict presentation panel with View difference, Keep local buffer, explicit Replace from observed disk, and manual Merge draft. No automatic three-way merge success claim. If base text is unavailable (restored dirty buffer), show base unknown and two-way comparison; never fabricate original disk version from current disk. Keep local does not write disk. Applying a merge changes only local buffer and stays dirty. Disk read failure/deletion retains explanatory state and local content; an explicit discard remains tied to captured local/remote revisions and must reject changed state. Reuse existing diff rendering, but retain conflict originals independent of Monaco model lifecycle.

3. **Close actual disk-write race separately.** Current ide_write_file(path,content) has no expected disk hash and can overwrite Agent/external edits after the last observation. A frontend-only comparison cannot provide acceptance “concurrent changes never overwrite.” Add host checked-write with expected disk hash/explicit missing expectation and scope-bound path authority; Windows same retained file handle/appropriate sharing verifies identity and current bytes before writing. New creation needs exclusive create; deletion/recreation/rename must fail stale rather than silently overwrite. Ordinary task readonly observation does not grant this write. Workspace/task action authorization is a separate dependency. All write actors that can race must be accounted for; an app mutex alone does not exclude external writers or existing handles. A staged candidate may block saving unresolved conflicts and state the remaining checked-write gap instead of claiming full concurrency acceptance.
