# AZ-018 read-only session metadata candidate

The new `commands/session_metadata.rs` exposes `read_existing(project, session_id)` and the host-only `SessionMetadata { workspace, workz, cwd }`. The root agent owns module export and replacing the normal kernel initialization call in `existing_binding`; this file does not register an IPC or activate the helper.

It opens only the canonical project `.agentz/piscis.db` using SQLite READ_ONLY, without directory creation, migrations, journal-mode changes or global Settings loading. A single transaction reads authorization fields and then the frame at the same snapshot. Required columns must exist; source NULL and invalid SQLite field types reject. It does not claim schema-version detection: the upstream session DB has no version contract for this helper. CodeZ and legacy `agentz` remain allowed; only plain WorkZ is allowed in the WorkZ namespace, with no pool session, team or pool metadata. WorkZ JSON errors reject. Frame length is queried before materializing the string and limited to 1 MiB.

Three actual SQLite fixtures are authored: normal kernel-created database read and byte preservation/missing database or session; namespace and WorkZ metadata rejection; strict BLOB field corruption, oversized frame and legacy missing-column rejection with byte preservation. These fixtures have not been compiled or run by this agent. Rustfmt and repository diff check exited 0; the latter reported existing LF/CRLF warnings.

Remaining boundary: this helper replaces session DB initialization only. `existing_binding` still may use `workz_overview` for the free-project source check, whose existing implementation can create host directories. The full IPC must not be described as filesystem-immutable until that call is separately replaced. The resolver still needs the caller's existing opaque scope, environment lease and final scope revalidation; this helper alone does not authorize an arbitrary project directory.
