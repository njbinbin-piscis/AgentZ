# AZ-041 editor buffer protection wiring

The CodeZ `index.tsx` now uses the separately tested `EditorConflictTracker` for synchronous project generation, unique open-tab identity, local edit revision and per-operation read/save request generation. A central tabs setter updates live refs before React renders and tracks opens/closes. Typing explicitly increments revision even when text is equal, so content equality is not used as the ABA guard.

External dirty-file deletion keeps the tab and unsaved buffer and displays an error. Confirmed reload captures the exact current revision without clearing dirty first; read failure, binary replacement, local typing, project switching or close/reopen cannot clean/overwrite the captured buffer. Save completion cleans only its matching capture; write failure retains dirty content and reports an error. Initial opens, diff/reveal navigation and asynchronous hot-exit restore also check project/request generations; restore refuses to overwrite newer editor mutations and retains persisted dirty buffers when file reading fails.

Review also found existing save-and-close paths removed tabs after failed writes. Those now reuse guarded save and retain tabs on failed/stale save or newer dirty edits. Bulk close records original tab identities, protects the project generation and preserves newly opened/reopened tabs. This does not add filesystem compare-and-swap: a successful physical write may still race external disk changes. No automatic overwrite, merge, retry, desktop acceptance or host atomic-write claim is made.

Reserved-path restoration consumes only saved text and never reads a disk path. Binary disk replacement also retains the saved dirty draft.

Recovery uses a dedicated read-only textarea plus explicit copy, not FileViewer/Monaco/LSP.
