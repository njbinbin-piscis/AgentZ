# AZ-038 host artifact integration: read-only design review

## Existing paths and authority

`workspaces/workz/agentArtifacts.ts` currently derives candidate paths from tool input (`path`/`file_path` etc.) and regex matches in tool result text. `normalizeArtifactPath` replaces backslashes and removes leading separators; this is a UI hint, not a durable artifact identity, successful creation proof, digest or version. Read/edit tools can also appear in this list. CodeZ `AssistantPanel.tsx` stores these paths in a per-session set and WorkZ collects them from persisted steps. Neither source establishes artifact ownership.

`ArtifactsDrawer.tsx` renders a path tree. `AgentFilePreview.tsx` resolves `workspaceDir || projectDir` plus the hint path through `artifactPaths.ts` and calls legacy `ideApi.readFile(fullPath)`; its parallel diff uses `ideApi.gitDiff(projectDir,path)`, which may target a different root from the isolated file. The resolver does not reject `..`, and should not be reused to authorize durable artifact reads. The new AZ-036 `TaskFileViewer` and `taskView`/`taskFiles` services already use opaque host project scopes, existing sessions, captured binding and relative paths; this is the appropriate observation boundary for current workspace files.

`agent_task_change_set` and `agent_task_file_view` in `commands/agent_task.rs` load a registered task environment and revalidate the checkout, then call `changes::collect/file_view` using the frozen base SHA. ChangeSet has head/base SHAs, per-path status/binary/source facts and runtime exclusions. This is a current Git checkout review; it is not a snapshot of produced reports, direct CodeZ output ownership, or immutable prior artifact bytes. Keep ChangeSet and artifact version contracts distinct.

## Minimal host integration proposal

Add dedicated commands/services for listing existing artifact versions and explicitly capturing a current task-relative output. Accept opaque scope handle, existing session, expected host binding and relative path; derive project/workspace/run/attempt on the host. Reuse `project_scope::lookup_for_main` plus final `with_verified_scope`, the environment execution lease, `task_view::resolve_observation/revalidate` and existing session/source checks. Never accept renderer absolute output roots, run ownership or hashes as authority. A captured revision must bind task/environment plus actual Run/Attempt where known; a missing Run is an explicit unsupported/missing condition rather than a fabricated association.

The new artifacts store can provide metadata DTOs with artifact ID/version, relative path, media type, content SHA256, byte size, capture time and host provenance. Immutable stored bytes are needed for claiming historical version availability: a digest of a mutable workspace path only detects change and cannot reopen old content. Capture must validate path containment, symlink/reparse policy, excluded credential/runtime paths and size budgets before opening; reread/check races and commit ordering remain implementation responsibilities. Listing should be bounded and read-only, with missing store distinguished from corrupt/unsupported schema. Metadata does not imply delivery accepted.

A first UI slice should be passive version listing plus plain-text source preview through the scoped artifact API. Keep the existing heuristic drawer labeled as current path hints until it consumes actual host versions. Do not route immutable versions through legacy absolute `ide_read_file`, current Git diff or user-selected workspaceDir. Generation plus complete task/environment/artifact/version identity must guard late replies when tasks change. Current-task file viewing can remain the independent AZ-036 reader.

## Reports, deletion and verification limits

The existing HTML report preview uses `iframe sandbox="allow-same-origin" srcDoc={content}` (no scripts). This blocks script execution but does not forbid remote images, CSS requests or links/forms by itself. Treat HTML bytes as untrusted report data; the minimum new-version preview is escaped source. A later rich-report preview needs an explicit isolated sandbox/resource policy and a verified restricted asset resolver rather than inheriting document origin or substituting workspace absolute paths. PDF/image legacy preview is not proof of durable artifact retrieval.

`agent_task_archive` preserves recoverable source snapshots; `agent_task_discard` uses the cleanup lease and `cleanup::retain_task`. These APIs should not silently delete version storage or reinterpret artifact listing as cleanup authorization. Define whether archive includes artifact bytes, whether retention tombstones metadata or removes bytes, and what restored task/environment IDs mean before exposing artifact deletion. The minimal slice needs no deletion command and must explicitly report unavailable archived bytes when not retained.

This agent only inspected local source and wrote this design evidence. No artifacts were captured, no files or tasks deleted, no build/model/GUI or report rendering acceptance performed. The parallel artifacts store and root host commands require their own actual SQLite/filesystem fixtures. Specific outstanding proofs: immutable bytes survive workspace edit/restart; wrong task/attempt/binding rejects; missing/corrupt stores differ; capture failures roll back; secret and escape paths reject; task cleanup/archive semantics are explicit; rich HTML preview makes no unauthorized external requests.
