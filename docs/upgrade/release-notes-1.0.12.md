# AgentZ 1.0.12 发布说明

发布日期：2026-10-24。版本号与 `CHANGELOG.md` 的 1.0.12 条目一致。

AgentZ 1.0.12 把右侧「变更」改成与 Git 分开的 Agent 修改审阅（可逐文件保留或撤销），并修正「产物」把目录读取和已删除临时文件算进去、刷新不消失、点击报文件找不到的问题。

## 变更

- **变更面板只审阅 Agent 的文件修改，不再混入 Git 状态。** 列出本会话中 `file_write` / `file_edit` 尚未「保留」或「撤销」的文件，按首次改动前的内容做净值，并和磁盘核对。Agent 写完又删掉的临时文件、以及改回去与原文一致的文件，不再出现。Git 未提交变更仍在源代码管理界面。
- **保留与撤销会写入日志。** 单文件和「全部保留 / 全部撤销」都会在文件日志里记下 `kept` 或 `undone`（旧的日志库打开时自动补上 `kept` 列）。刷新或重启后，已接受的修改不会再回到列表。撤销把文件恢复到审阅基线；Agent 新建的文件则被删除。
- **产物只来自写入类工具**（`file_write`、`file_edit` 及名称同类的产出工具）。读取、列目录、搜索不再把目录或文件记成产物。刷新会去掉已经不是普通文件的路径；状态为已删除的变更条目不能点开。

## 修复

- 读取项目子目录不再使该目录成为产物。
- Agent 编写并在测试后删除的临时文件仍留在变更和产物中，点刷新也不消失。
- 点击已经不存在的变更文件会在编辑器中打开并报「文件找不到」。

## 范围说明

通过 `shell` 或脚本直接改文件不会进入这份审阅日志，因此不能从变更面板撤销；只有 `file_write` 和 `file_edit` 会被记录。若 shell 删掉的是 Agent 先前编辑过的文件，该条目会显示为已删除（D），可以撤销以恢复审阅基线。

## 待真机冒烟

- Agent 用 `file_write` 新建文件、再编辑、再删除：变更里先出现 A，删除后消失或变为可撤销的 D，产物在刷新后不再列出。
- 只执行 `file_list` / `file_read` 不产生产物。
- 单文件与全部的保留、撤销在刷新和重启后仍然生效；撤销后的文件内容回到 Agent 动手之前。
- Git 面板仍显示仓库状态，与变更面板互不影响。
